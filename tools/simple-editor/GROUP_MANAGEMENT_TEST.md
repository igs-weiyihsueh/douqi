# 群組物件管理機制修正 - 測試驗證指引

## 🎯 **修正目標**
確保群組生成的物件不出現在物件管理列表中，只能透過群組面板管理，實現清晰的職責分工。

## 🧪 **核心測試項目**

### **✅ 1. 物件列表過濾測試**

#### **測試步驟**：
1. **重新載入編輯器** (Ctrl+F5，確認v8.1-group-management)
2. **放置獨立物件** → 點擊空白處生成2個獨立物件
3. **檢查物件列表** → 應顯示「物件管理 [共 2 個]」
4. **創建群組** → 選中物件，新增群組，生成群組物件
5. **檢查列表變化** → 應顯示「物件管理 [獨立: 2 | 群組: 3]」

#### **預期結果**：
- ✅ **列表數量不變**: 物件管理列表仍然只顯示2個獨立物件
- ✅ **統計正確**: 標題顯示「獨立: 2 | 群組: 3」
- ✅ **底部提示**: 「另有 3 個群組物件 (在群組面板管理)」

### **✅ 2. 群組物件交互限制測試**

#### **測試步驟**：
1. **直接點擊群組物件** → 點擊畫面上的群組生成物件
2. **檢查控制台** → F12查看控制台訊息
3. **檢查選中狀態** → 群組物件不應被選中
4. **檢查屬性面板** → 不應顯示群組物件的屬性

#### **預期結果**：
- ✅ **無法選中**: 群組物件點擊無效，不會被選中
- ✅ **視覺反饋**: 群組物件短暫閃爍(0.2秒)
- ✅ **控制台提示**: 「🔒 群組物件 "木箱_群組1_1" 只能透過群組面板管理」
- ✅ **來源資訊**: 「所屬群組: 群組1 (位置 1)」

### **✅ 3. 刪除保護機制測試**

#### **測試A - 群組物件直接刪除保護**：
理論上群組物件不會出現在列表中，但如果出現（異常情況），應該被保護。

#### **測試B - 主物件刪除確認**：
1. **選中包含群組的主物件** → 在物件列表中選中
2. **點擊刪除按鈕** → 點擊列表中的 × 按鈕
3. **檢查確認對話框** → 應出現確認提示

#### **預期對話框內容**：
```
此物件包含 1 個已生成的群組，刪除後將一併移除所有群組物件。是否繼續？
```

#### **測試結果**：
- ✅ **點擊取消**: 主物件和群組物件都保留
- ✅ **點擊確認**: 主物件和所有相關群組物件都被刪除

### **✅ 4. 數據一致性測試**

#### **測試步驟**：
1. **檢查群組物件標記** → F12控制台執行：
   ```javascript
   // 檢查entities陣列中的群組物件標記
   entities.forEach((e, i) => {
     if (e.userData.isGroupMember) {
       console.log(`群組物件 ${i}:`, e.userData.name, e.userData.clusterSource);
     }
   });
   ```

2. **檢查過濾邏輯** → 執行：
   ```javascript
   // 檢查過濾結果
   const independent = entities.filter(e => !e.userData.isGroupMember);
   const groups = entities.filter(e => e.userData.isGroupMember);
   console.log(`獨立: ${independent.length}, 群組: ${groups.length}`);
   ```

#### **預期結果**：
- ✅ **標記正確**: 群組物件有 `isGroupMember: true`
- ✅ **來源完整**: 群組物件有完整的 `clusterSource` 資訊
- ✅ **過濾正確**: 過濾邏輯正確分離兩類物件

2. **檢查標題更新** → 物件管理標題的統計標籤
3. **檢查底部提示** → 列表底部的群組物件提示

## 🚨 **可能的問題與解決**

### **問題1**: 群組物件仍出現在列表中
**排查**: 檢查 `isGroupMember` 標記是否正確設置
**解決**: 確認createEntity函數正確傳遞並保存標記

### **問題2**: 點擊群組物件無反應
**排查**: 檢查點擊事件處理邏輯
**解決**: 確認事件處理中的 `isGroupMember` 檢查

### **問題3**: 統計數字不正確
**排查**: 檢查過濾邏輯和統計計算
**解決**: 確認 `entities.filter()` 條件正確

### **問題4**: 刪除主物件時群組物件未清理
**排查**: 檢查 `deleteClusterObjects` 函數
**解決**: 確認群組物件的 `clusterSource` 匹配邏輯
