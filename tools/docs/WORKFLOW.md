# 🔄 編輯器協作工作流程

> 場景編輯器與關卡編輯器的完整協作流程，從概念設計到遊戲部署的標準化工作方式。

## 📋 流程概覽

### 工作流程圖
```
概念設計 → 場景編輯 → 關卡配置 → 整合測試 → 遊戲部署
    ↓         ↓         ↓         ↓         ↓
  文檔規劃   3D場景    遊戲邏輯   功能驗證   發佈上線
```

### 參與角色
- **設計師**：負責概念設計和視覺規劃
- **場景師**：使用場景編輯器建立 3D 環境
- **關卡師**：使用關卡編輯器設計遊戲邏輯
- **程式師**：整合測試和技術支援
- **企劃**：品質控制和平衡調整

## 🎯 階段一：概念設計 (1-2天)

### 1.1 需求分析
**負責人**：設計師 + 企劃
**產出物**：關卡設計文檔

**工作內容**：
- 確定關卡主題和風格 (如：森林、城市、地下城)
- 規劃關卡目標和勝利條件
- 設計敵人類型和 AI 行為
- 規劃道具和獎勵機制

**文檔模板**：
```markdown
# 關卡設計案 - {關卡名稱}

## 基本資訊
- 關卡代號：level_xxx
- 主題風格：{主題描述}
- 預估難度：easy/normal/hard
- 預計遊戲時長：{X}分鐘

## 視覺設計
- 場景描述：{環境描述}
- 主要地形：{地形特色}
- 建築物件：{建築清單}
- 光照風格：{光照描述}

## 遊戲邏輯
- 主要目標：{目標描述}
- 敵人配置：{敵人類型和數量}
- 道具設計：{道具類型和功能}
- 特殊機制：{獨特玩法}
```

### 1.2 資源準備
**負責人**：美術 + 技術
**產出物**：3D 模型、貼圖、音效資源

**資源清單**：
- **3D 模型**：地形、建築、道具、角色 (.fbx 格式)
- **貼圖材質**：環境貼圖、UI 貼圖 (.jpg/.png 格式)  
- **音效資源**：背景音樂、環境音效、特效音 (.ogg 格式)
- **配置檔案**：敵人資料、道具資料 (.json 格式)

## 🏗️ 階段二：場景編輯 (2-3天)

### 2.1 環境建置
**負責人**：場景師
**工具**：場景編輯器 (`tools/scene-editor/`)
**產出物**：`.douqi.json` 場景檔案

**操作步驟**：
1. **建立新場景**
   ```bash
   cd tools/scene-editor
   npm run build
   # 開啟 dist/editor.html
   ```

2. **基礎地形擺放**
   - 載入地面模型 (ground_tile.fbx)
   - 設定合適的縮放比例 (通常 10x10 或更大)
   - 配置地面碰撞盒 (Box, Static, Non-Trigger)

3. **建築物件佈局**
   - 按設計圖擺放建築模型
   - 調整位置、旋轉、縮放
   - 設定建築物碰撞屬性

4. **環境細節添加**
   - 放置裝飾物件 (樹木、石頭、道具等)
   - 調整細節位置增加真實感
   - 確保玩家移動路徑暢通

### 2.2 材質和光照
**工作內容**：
1. **材質配置**
   - 為每個物件設定合適的貼圖
   - 調整 UV 平鋪和偏移值
   - 設定材質屬性 (金屬度、粗糙度等)

2. **光照設計**
   ```
   環境光設定：
   - 顏色：#ffffff (日間) 或 #404080 (夜間)
   - 強度：0.3-0.5

   太陽光設定：
   - 顏色：#fff8dc (暖白) 或 #87ceeb (冷白)
   - 強度：0.8-1.2
   - 方向：[100, 300, 150] (可調整)
   ```

3. **特效添加** 
   - 環境粒子效果 (灰塵、落葉等)
   - 大氣效果 (霧氣、光束等)
   - 互動特效 (觸發區域提示等)

### 2.3 場景優化和匯出
**檢查清單**：
- [ ] 所有物件材質正確顯示
- [ ] 碰撞設定符合遊戲需求
- [ ] 光照效果自然合理
- [ ] 整體效能在可接受範圍
- [ ] 場景檔案大小合理 (< 1MB)

**匯出設定**：
```
檔案名稱：{關卡代號} (如：level_001, forest_stage)
儲存位置：public/scenes/{檔案名稱}.douqi.json
檢查項目：JSON 格式正確，路徑引用有效
```

## 🎮 階段三：關卡配置 (2-3天)

### 3.1 基礎配置
**負責人**：關卡師
**工具**：關卡編輯器 (`tools/level-editor/`)
**依賴**：階段二的場景檔案

**操作步驟**：
1. **啟動關卡編輯器**
   ```bash
   cd tools/level-editor  
   npm run build
   # 開啟 dist/index.html
   ```

2. **載入基礎場景**
   - 在「場景目標」輸入框填入場景名稱
   - 確認對應的 `.douqi.json` 檔案存在
   - 驗證場景載入正常

3. **設定關卡基本資訊**
   ```json
   {
     "id": "level_001",
     "name": "森林試煉",
     "difficulty": "normal",
     "timeLimit": 300,
     "scoreTarget": 2000
   }
   ```

### 3.2 遊戲實體配置
**工作內容**：
1. **玩家起始點設定**
   ```json
   {
     "playerStartPosition": [-5, 0.5, -5],
     "playerStartRotation": [0, 45, 0],
     "respawnPoints": [
       {"id": "checkpoint_1", "position": [0, 0.5, 0]},
       {"id": "checkpoint_2", "position": [5, 0.5, 5]}
     ]
   }
   ```

2. **敵人配置**
   ```json
   {
     "id": "enemy_group_1",
     "type": "patrol_unit",
     "count": 3,
     "spawnPoints": [
       {"position": [2, 0, 2], "rotation": [0, 0, 0]},
       {"position": [4, 0, -2], "rotation": [0, 90, 0]}
     ],
     "properties": {
       "health": 80,
       "attackPower": 15,
       "moveSpeed": 2.5,
       "aiType": "patrol",
       "patrolRadius": 3.0
     }
   }
   ```

3. **道具分佈**
   ```json
   {
     "collectibles": [
       {
         "type": "energy_orb",
         "positions": [[1,1,1], [3,1,-1], [-2,1,2]],
         "value": 50
       },
       {
         "type": "health_pack", 
         "positions": [[-1,0.5,3], [2,0.5,-3]],
         "healAmount": 25
       }
     ],
     "powerups": [
       {
         "type": "attack_boost",
         "position": [0, 1, 4],
         "duration": 15,
         "multiplier": 1.5
       }
     ]
   }
   ```

### 3.3 遊戲邏輯設計
**核心系統**：
1. **目標系統**
   ```json
   {
     "objectives": [
       {
         "id": "primary_goal",
         "type": "collect",
         "description": "收集15個能量球",
         "target": 15,
         "reward": 1000,
         "required": true
       },
       {
         "id": "bonus_goal",
         "type": "time_bonus",
         "description": "在3分鐘內完成",
         "target": 180,
         "reward": 500,
         "required": false
       }
     ]
   }
   ```

2. **事件觸發**
   ```json
   {
     "events": [
       {
         "id": "enemy_wave_1",
         "type": "spawn_wave",
         "triggerTime": 60,
         "enemies": [
           {"type": "fast_enemy", "count": 5, "interval": 2}
         ]
       },
       {
         "id": "boss_appearance", 
         "type": "conditional_spawn",
         "triggerCondition": {
           "type": "collectibles_remaining",
           "operator": "<=",
           "value": 3
         },
         "boss": {
           "type": "forest_guardian",
           "position": [0, 0, 8],
           "health": 300
         }
       }
     ]
   }
   ```

## 🧪 階段四：整合測試 (1-2天)

### 4.1 功能測試
**負責人**：關卡師 + 程式師
**測試項目**：

1. **載入測試**
   - [ ] 場景檔案正確載入
   - [ ] 所有物件正常顯示
   - [ ] 材質和光照效果正確
   - [ ] 碰撞檢測正常運作

2. **遊戲邏輯測試**
   - [ ] 玩家起始位置正確
   - [ ] 敵人 AI 行為符合預期
   - [ ] 道具收集功能正常
   - [ ] 事件觸發時機正確
   - [ ] 勝利/失敗條件有效

3. **效能測試**
   - [ ] 關卡載入時間 < 5秒
   - [ ] 遊戲執行流暢 (FPS > 30)
   - [ ] 記憶體使用量合理
   - [ ] 無明顯卡頓或掉幀

### 4.2 平衡調整
**調整要點**：
1. **難度平衡**
   - 根據測試結果調整敵人數量和血量
   - 優化道具分佈和獎勵機制
   - 平衡時間限制和目標要求

2. **流暢度優化**
   - 調整敵人刷新時機和密度
   - 優化事件觸發間隔
   - 改善玩家體驗流程

**測試記錄模板**：
```markdown
# 關卡測試報告 - {日期}

## 測試概況
- 測試版本：v{版本號}
- 測試時長：{X}小時  
- 測試人員：{姓名清單}

## 功能測試結果
- 載入速度：{X}秒
- 運行流暢度：{良好/一般/需優化}
- 發現 Bug：{數量} 個

## 平衡性評估
- 難度評級：{過難/適中/過易}
- 通關時間：平均 {X} 分鐘
- 建議調整：{具體建議}
```

### 4.3 檔案整理和版本控制
**最終檢查**：
1. **檔案完整性**
   ```
   public/scenes/{關卡名}.douqi.json          ✅
   public/assets/data/levels/{關卡名}.json     ✅
   tools/docs/測試報告.md                      ✅
   ```

2. **版本提交**
   ```bash
   git add .
   git commit -m "feat: 新增關卡 {關卡名} - 完成場景編輯和關卡配置"
   git push origin main
   ```

## 🚀 階段五：遊戲部署 (半天)

### 5.1 打包發佈
**負責人**：程式師
**工作內容**：
1. **最終建置**
   ```bash
   # 確保所有編輯器都已建置完成
   cd tools/scene-editor && npm run build
   cd ../level-editor && npm run build  
   cd ../..
   
   # 執行遊戲主程式建置
   npm run build
   ```

2. **資源優化**
   - 壓縮場景檔案大小
   - 優化圖片和音效資源
   - 清理未使用的檔案

3. **部署到 GitHub Pages**
   ```bash
   npm run deploy
   # 或手動推送 dist/ 目錄
   ```

### 5.2 品質保證
**最終檢查清單**：
- [ ] 關卡在正式環境下可正常載入
- [ ] 所有功能運作正常
- [ ] 效能表現達標
- [ ] 沒有明顯 Bug 或問題
- [ ] 使用者體驗良好

## 📊 工作流程範本

### 時程安排 (以單關卡為例)
```
第1天：概念設計 + 資源準備
第2-3天：場景編輯 + 材質光照  
第4-5天：關卡配置 + 邏輯設計
第6天：整合測試 + 平衡調整
第7天：最終優化 + 部署發佈

總計：1週 (7個工作天)
```

### 溝通協調
**日常 Sync**：
- 每日站會 (15分鐘)：進度同步、問題討論
- 每週 Review (1小時)：階段成果展示、下週規劃

**里程碑檢查**：
- 階段二完成：場景預覽 Demo
- 階段三完成：關卡試玩 Demo  
- 階段四完成：整合測試報告
- 階段五完成：正式版本發佈

## ⚠️ 注意事項與最佳實踐

### 常見問題預防
1. **檔案相依性**：確保場景檔案在關卡配置前完成
2. **路徑一致性**：統一使用相對路徑和標準命名
3. **版本同步**：定期同步程式碼，避免衝突
4. **效能監控**：及時發現和解決效能瓶頸

### 團隊協作建議
1. **明確分工**：每個階段都有明確的負責人
2. **定期溝通**：避免重複工作和認知偏差
3. **文檔記錄**：重要決策和變更及時記錄
4. **品質優先**：不為了趕進度而犧牲品質

### 工具使用規範
1. **編輯器版本**：團隊使用統一版本的編輯器
2. **命名規範**：遵循專案統一的命名慣例
3. **備份策略**：重要檔案定期備份和版本控制
4. **安全操作**：避免使用可能導致系統阻塞的命令
