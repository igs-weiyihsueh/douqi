# 編輯器邊界修正詳細對照

## 🎯 修正目標
確保編輯器邊界與實際遊戲的玩家活動區域 (arena) 完全一致。

## 🔍 問題發現過程

### 原始錯誤設定
```javascript
const GAME_WORLD_WIDTH = 1600;   // ❌ 錯誤來源
const GAME_WORLD_HEIGHT = 1200;  // ❌ 錯誤來源
entity.x = Math.max(-halfWidth + 20, Math.min(halfWidth - 20, entity.x)); // ❌ 任意內縮
```

### 錯誤來源分析
- **1600×1200** 來自 `src/scenes/LevelGameScene.ts`
- 但 `LevelGameScene` 只是**關卡編輯器整合示範場景**
- 使用 `createTemporaryAssets` 臨時素材，非實際遊戲
- 真正的主遊戲是 `src/scenes/GameScene.ts`

## 🎮 實際遊戲邊界結構

基於 `src/scenes/GameScene.ts` + `src/config.ts` 分析：

### 多層邊界結構
1. **邏輯解析度**: 1280×720 (`GameConfig.width/height`)
2. **玩家活動區 (arena)**: 1040×600 (`GameConfig.stage.arenaW/arenaH`) ⭐ **關鍵邊界**
3. **單個子區含遠景 (slot)**: 1420×980 (arena + 2×sceneMargin 190)
4. **整個可捲動世界**: 4660×980 (3個slot水平並排 + gap×2)

### 為什麼選擇 arena (1040×600)？
- **玩家實際活動範圍**: 物理世界限制玩家在此區域內移動
- **物件生效區域**: 只有在 arena 內的物件才會與玩家互動
- **關卡設計核心**: 關卡編輯器應該對應實際遊戲邏輯區域

## ✅ 修正後設定

### 世界尺寸
| 項目 | 修正前 | 修正後 | 遊戲實際 |
|------|--------|--------|----------|
| 寬度 | 1600px | **1040px** | `stage.arenaW` |
| 高度 | 1200px | **600px** | `stage.arenaH` |
| 比例 | 4:3 | **52:30** | arena 實際比例 |

### 邊界內縮
| 內縮類型 | 數值 | 用途 | 來源 |
|----------|------|------|------|
| **breakable.edgeInset** | **60px** | 可破壞物安全距離 | config.ts ⭐ **採用** |
| spawn.edgeInset | 90px | 敵人生成區域內縮 | config.ts |
| stage.arrowInset | 70px | 箭頭指示內縮 | config.ts |
| exitInset | 60px | 出口區域內縮 | config.ts |

選擇 `breakable.edgeInset = 60px` 的原因：
- 可破壞物件與編輯器中的物件性質最相近
- 提供合理的安全邊距，避免物件過於靠近邊界
- 與遊戲實際行為一致

### 攝影機調整
```javascript
// 因為世界變小，需要調整縮放以保持良好視野
let cameraZoom = 0.6; // 從 0.4 調整為 0.6
```

## 📊 修正效果對比

### 可用空間變化
| 項目 | 修正前 | 修正後 | 變化 |
|------|--------|--------|------|
| **總邊界** | 1600×1200 | **1040×600** | -35% / -50% |
| **邊界內縮** | 20px | **60px** | +200% (更安全) |
| **可放置區域** | 1560×1160 | **920×480** | -41% / -59% |
| **可放置半徑** | 780×580 | **460×240** | 更緊湊，更真實 |

### 視覺效果
- **修正前**: 編輯器看起來很大，但與實際遊戲不符
- **修正後**: 編輯器大小與實際遊戲 arena 完全一致
- **縮放調整**: 0.6倍縮放確保整個 arena 在視野內清晰可見

## 🧪 驗證方法

### 啟動驗證
編輯器控制台會顯示：
```
=== 邊界設定驗證 ===
遊戲世界尺寸: 1040x600 (arena 活動區域)
邊界內縮: 60px (基於 breakable.edgeInset)
物件可放置區域: 920x480 (460px內)
```

### 視覺檢查
1. **邊界框**: 紅色邊界線應該呈現 1040×600 的矩形
2. **物件放置**: 物件拖拽時在距離邊界60px處停止
3. **視野範圍**: 整個 arena 應該在默認縮放下清晰可見
4. **比例感**: 應該感覺比之前更緊湊，但更真實

### 功能測試
1. **拖拽測試**: 物件不能拖拽到邊界外60px
2. **群組測試**: 群組中心也遵循相同的邊界限制
3. **生成測試**: 新生成的物件在中央區域，符合邊界限制

## 🎯 設計建議

### 關卡設計時
- **核心區域**: 在 arena 中央 (±400×±240) 放置主要內容
- **邊緣利用**: 邊界附近可放置裝飾或次要元素
- **安全距離**: 重要物件避免太靠近60px邊界內縮線

### 群組設計時
- **群組大小**: 考慮 arena 尺寸，避免群組範圍超出邊界
- **密度控制**: 在較小的 arena 中，物件密度需要更精心設計
- **陣型選擇**: 根據 arena 比例選擇合適的陣型

當匯出給遊戲使用時，需要進行座標轉換：
- 編輯器中心 (0,0) → 遊戲 arena 左上角 + (520, 300)
- 但邊界設定現在已完全對齊，轉換更準確
